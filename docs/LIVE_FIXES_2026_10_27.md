# Live cooking interface corrections — 2026-10-27

- Source-backed evidence and references remain in backend metadata. Cooking cards no longer render book names, source links, page numbers or validation notes.
- Automatic book cards now require a specific supported dish match. Generic softening words cannot attach vegetable/tomato guidance to gizzards. Vegetable acidity guidance requires a vegetable/soup dish with vegetables and tomatoes; meat guidance distinguishes explicitly named tough and lean cuts. Marinade advice requires an explicit marinade/brine context.
- Cards explain the practical consequence in plain language. They do not describe an application of a culinary principle as a step from a supplied recipe.
- The chef screen embeds the existing reporting PWA using the same JSON-defined icon/parameter forms. Cook opens appliance setting, duration and equipment; cutting and adding ingredients retain their dedicated fields. The embedded frame stays attached across parent renders so draft values survive.
- Guest reports save locally with timestamps and timers. Private two-device synchronization still requires account sign-in. Same-origin, source-checked parent/frame messages share the existing page-memory login without putting credentials in URLs or browser storage. Signing out of the parent clears the embedded account.
- Restored the stopped existing PostgreSQL container without replacing its volume. Windows rejected its previous host port; the private local configuration now uses `15432`. Applied migration `0003` and restarted only the verified Chef process.
- Repaired the Cloudflare origin behind the existing permanent Workers address. `scripts/cloudflare_keepalive.py --watch` checks it every thirty seconds, repairs a failed origin, and updates the existing gateway. The check falls back to a real browser when Windows TLS clients cannot verify an otherwise reachable Cloudflare site. Credentials stay in the existing ignored runtime directory. The keepalive must run alongside Chef; it is not a hosted backend or a reboot/startup service.

Validated the real public site with `scripts/check_live_dish_reporting.py`: relevant plain-language cards, absence of book references, embedded action icons, heat/time controls, local report/timer and draft preservation. Local readiness and `/report/` return HTTP 200. Unit regressions and the two-device/offline browser regression also pass.
